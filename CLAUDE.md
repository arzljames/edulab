# EduLab

An online hub where teachers share teaching materials and resources, and adapt them with AI (by grade or reading level, language, format, and accommodations).

## Tech stack
- **Vite + React + TypeScript** (strict mode)
- **TanStack Router**: file-based, type-safe routing (`@tanstack/router-plugin/vite`, `autoCodeSplitting: true`)
- **TanStack Query** (+ Devtools): server state (fetching, caching, mutations)
- **Zustand**: client-only global state
- **Zod**: schemas and runtime validation (forms, API responses, route search params)
- **React Hook Form** + `@hookform/resolvers/zod`: forms
- **Axios**: HTTP client (use `fetch` only for streaming endpoints)
- **shadcn/ui** + Tailwind CSS (UI primitives in `src/components/ui/`)
- **Vitest + React Testing Library + MSW**: testing

## Commands
```bash
npm run dev          # start dev server (also regenerates routeTree.gen.ts)
npm run build        # type-check + production build
npm run lint         # eslint
npx tsc --noEmit     # type-check only
npx vitest run       # run tests once
npx shadcn@latest add <component>   # add a shadcn primitive
```

## Architecture: feature-based (ALWAYS)

All product code lives in a **feature folder**. The only exception is `src/routes/`, which TanStack Router's file-based routing requires. Route files there are **thin**: they wire URL → feature and contain no business logic.

```
src/
├── main.tsx                  # QueryClientProvider + RouterProvider
├── routeTree.gen.ts          # GENERATED by the router plugin; never edit
├── routes/                   # THIN route files only (file-based routing)
│   ├── __root.tsx            # createRootRouteWithContext<RouterContext>(), root layout, devtools
│   ├── index.tsx             # /
│   ├── login.tsx             # public
│   ├── _authenticated.tsx    # pathless layout: beforeLoad auth guard + app shell
│   └── _authenticated/
│       ├── dashboard.tsx
│       ├── library.tsx                     # validateSearch + loaderDeps + loader
│       ├── resources/$resourceId.tsx
│       ├── resources/$resourceId.adapt.tsx
│       └── ...
├── app/
│   ├── router.ts             # createRouter({ routeTree, context, defaultPreload: 'intent', ... }) + Register
│   ├── router-context.ts     # RouterContext type: { queryClient, auth }
│   └── layouts/              # AppShell, AuthLayout (used by layout routes)
├── features/
│   └── <feature-name>/       # kebab-case, e.g. resources, adaptation, auth
│       ├── api/
│       │   ├── endpoints.ts
│       │   ├── <feature>.api.ts      # pure fetchers (Axios + Zod parse)
│       │   └── <feature>.queries.ts  # key factory, queryOptions, query/mutation hooks
│       ├── components/       # feature UI components
│       ├── hooks/            # non-data feature hooks
│       ├── pages/            # page components rendered by route files
│       ├── schemas/          # Zod: forms, responses, AND route search params
│       ├── stores/           # Zustand (client-only state), only if needed
│       ├── types.ts          # z.infer types
│       ├── utils/
│       ├── config.ts         # optional constants
│       └── index.ts          # PUBLIC API: the only file other features and routes import
├── components/
│   ├── ui/                   # shadcn generated, never edit for feature logic
│   └── shared/               # cross-feature presentational components
├── lib/
│   ├── axios.ts              # single Axios instance + interceptors
│   ├── api-error.ts          # ApiError type + normalizer
│   ├── query-client.ts       # QueryClient + defaults
│   └── utils.ts              # cn() etc.
├── config/
└── test/                     # setup.ts, utils.tsx (renderWithProviders / renderRoute), MSW, factories
```

### Feature rules
1. **Public API only.** Routes and other features import from `@/features/<name>` (its `index.ts`). No deep imports.
2. **No circular feature dependencies.** Shared things go to `components/shared/`, `lib/`, or a new feature.
3. **Colocate tests** next to the code.
4. Path alias `@/` → `src/`.

## Routing rules (TanStack Router)

- **File-based** routes in `src/routes/`, generated into `routeTree.gen.ts`. Never edit the generated file.
- **Thin route files** only set: `validateSearch`, `loaderDeps`, `beforeLoad`, `loader`, `component`, `pendingComponent`, `errorComponent`, `notFoundComponent`. Everything they reference is imported from `@/features/<name>`.
- **Router context** carries `{ queryClient, auth }`. Use `createRootRouteWithContext<RouterContext>()`.
- **Auth guard**: the `_authenticated.tsx` pathless layout's `beforeLoad` checks `context.auth` and `throw redirect({ to: '/login', search: { redirect: location.href } })`. Role checks (e.g., admin) also go in `beforeLoad`.
- **Search params are state.** Validate them with a Zod schema from the feature (`validateSearch: zodValidator(librarySearchSchema)` via `@tanstack/zod-adapter`, with `fallback()` defaults). Read them with `Route.useSearch()` in route files, or `getRouteApi('<route-id>').useSearch()` in feature components. Update them with `navigate({ search: (prev) => ({ ...prev, page: 2 }) })`.
- **Loaders + Query**: loaders call `context.queryClient.ensureQueryData(featureQueryOptions(...))`, and components read the data with `useSuspenseQuery(sameOptions)`. The Query cache is the single source of truth, so don't use `useLoaderData` for server data. Declare the search params a loader depends on in `loaderDeps`.
- **Router defaults**: `defaultPreload: 'intent'`, `defaultPreloadStaleTime: 0` (Query handles freshness), `scrollRestoration: true`, and default pending, error, and not-found components.
- **Links are type-safe**: `<Link to="/resources/$resourceId" params={{ resourceId }}>`. Never build URL strings by hand. For shadcn buttons use `<Button asChild><Link …/></Button>`.
- **Code splitting** is automatic (`autoCodeSplitting`). Don't hand-roll `React.lazy` for routes.
- Use `useBlocker` to warn before leaving a page with unsaved form edits or an in-progress AI generation.

## Core conventions

**Data flow:** route loader / component → query or mutation hook (`<f>.queries.ts`) → fetcher (`<f>.api.ts`) → `lib/axios.ts`
- Components never call Axios or fetchers directly.
- Every API response is parsed with Zod in the fetcher.
- Types come from `z.infer`.

**State placement:**
| State | Where |
|---|---|
| Server data | **TanStack Query**, never Zustand |
| Filters, search, pagination, sort, tabs | **Router search params** (Zod-validated), which feed into query keys |
| Path identity (ids) | **Route params** |
| Form values | **React Hook Form** |
| One-component UI state | `useState` |
| Client-only cross-cutting state (auth token, streamed AI text, UI prefs) | **Zustand** |

**TanStack Query rules:** a key factory per feature (no inline keys). `queryOptions` are shared by loaders and components. Pass `signal` to fetchers. Mutations invalidate precisely. Quick toggles use optimistic updates with rollback. `useInfiniteQuery` for library browsing. Poll adaptation jobs with `refetchInterval` until a terminal status. On logout: `queryClient.clear()`, reset the stores, then `router.invalidate()` and redirect.

**Forms:** Zod schema + `zodResolver` + complete `defaultValues` + shadcn `Form`. Submit via mutations. After a successful create, `navigate({ to: '/resources/$resourceId', params })`.

**UI:** every data view handles loading (route `pendingComponent` / Skeleton), empty, error (route `errorComponent` with `router.invalidate()` retry), and success. Build mobile-first and accessible (WCAG 2.2 AA).

**TypeScript:** no `any`, no unchecked `as` on API data, and export props types.

**Security:** AI provider keys stay on the backend. Sanitize user- or AI-generated HTML with DOMPurify. Route guards are for UX only; the backend enforces permissions.

**AI output:** never auto-publish. Teachers review and edit before saving. Keep provenance and credit the original author. Respect licenses.

**Copy:** plain, teacher-friendly language.

## Subagents: delegate proactively

Specialized subagents live in `.claude/agents/`. **Delegate to them instead of doing specialist work inline.** Run independent agents in parallel.

| When the task involves… | Use |
|---|---|
| Route files, guards, search params, loaders, links, navigation | `routing-specialist` |
| Components, pages, layouts, shadcn | `ui-component-builder` |
| Forms, Zod schemas (form, response, search), validation | `form-schema-specialist` |
| Where state should live, Zustand stores (client-only) | `state-architect` |
| Endpoints, Axios, TanStack Query (keys, queries, mutations, cache), uploads | `api-integration-engineer` |
| Anything in the AI adaptation flow | `ai-adaptation-specialist` |
| Writing or fixing tests | `test-engineer` |
| Reviewing changes before commit or PR | `code-reviewer` (read-only) |
| Accessibility checks | `accessibility-auditor` (read-only) |
| Slowness, bundle size, re-renders, preloading | `performance-optimizer` |

### Standard workflow for a new feature or significant change
1. **Plan**: outline the feature folder, routes (paths, search params, guards), schemas, endpoints, query keys, queries and mutations, a client store (only if needed).
2. **Schemas and data layer**: `form-schema-specialist` + `api-integration-engineer` in parallel.
3. **Routes**: `routing-specialist` (route files, `validateSearch`, loaders using the feature's `queryOptions`, guards).
4. **Client state**: `state-architect`, only if client-only global state is needed.
5. **UI**: `ui-component-builder` (plus `ai-adaptation-specialist` for adaptation work).
6. **Tests**: `test-engineer`.
7. **Quality gate**: `code-reviewer` + `accessibility-auditor` in parallel. Fix any Critical findings.
8. Verify `npx tsc --noEmit`, `npm run lint`, and `npx vitest run` all pass.

To scaffold a new feature, use **`/new-feature <name> [description]`**.

## Don'ts
- Don't put logic in `src/routes/*` beyond route config. Don't edit `routeTree.gen.ts`.
- Don't use React Router, `window.location`, or hand-built URL strings.
- Don't create top-level `services/`, `stores/`, `schemas/`, or `hooks/` folders, and don't deep-import across features.
- Don't put server data in Zustand, and don't fetch with `useEffect` + `useState`.
- Don't mirror search params, form state, or query data into Zustand.
- Don't edit `src/components/ui/*` for feature needs.
- Don't add dependencies without saying why.
